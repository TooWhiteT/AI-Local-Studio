## 队列、恢复与审核

- 在首个镜头已进入 5090 的运行队列时重启 Studio。恢复后 attempt 和 prompt ID 保持一致，成功入库一次。按 SSE 游标回放该任务的 14 条事件，含采样进度和成功终态。
- 两镜头批量请求重复发送，返回相同批次和相同子任务 ID。四次成功渲染的 GPU 租约时间互不重叠；另一个排队中取消的任务没有外部 prompt ID。
- 在副本中临时移开已审核源图，任务在提交 GPU 前失败。恢复源图并重试后，同一任务产生新的 attempt 并成功，规划和实际解码均为 73 帧。
- 兼容路径中，运行中取消转为 CANCEL_REQUESTED，继续持有租约直至引擎结束，最终没有登记视频版本。[SSE、重试与取消记录](../storage/m3-5090/final.json)
- 同卡 Qwen 生成期间提交了另一项 H3 任务。文字租约结束 31.392 秒后，工作台确认 llama.cpp 已休眠才取得视频租约。接着按该视频的 prompt ID 请求取消，真实 ComfyUI history 返回 `execution_interrupted`，输出数量为零。[Qwen 与 H3 互斥、定向取消回执](../storage/m3-5090/mixed.json)
- 浏览器从候选帧及绑定的参考资产发起渲染，查看、审核或弃用结果。历史版本继续引用当时的媒体文件，前端及数据库检查过期输入、跨项目引用和并发审核冲突。

## 真实模板来源

首帧及首尾帧模板使用 FL2VA 和 8 步 LoRA。单参考图 R2V 模板使用独立的 Ref2VA 和 4 步 LoRA，以 `<Picture 1>` 引用选定角色。三份 API 图均来自目标机 ComfyUI 前端，并已核对实际执行回执。首尾帧和参考图模板首次通过原生画布的 prompt 分别是 `c18482ed-89e0-4e7d-9759-1f9d2f22ead5` 和 `fab9dbf4-653b-432b-b72b-f3d3291fbd97`。[官方 H3 模板说明](https://docs.comfy.org/tutorials/video/minimax/minimax-h3-native)
